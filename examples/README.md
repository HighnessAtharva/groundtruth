# Examples

Three real articles, three source types, three module combinations. **All three fail
on the first run, on purpose.** A green example teaches nothing.

| If you want to see | Open | Offline | Modules on |
|---|---|---|---|
| The smallest possible setup, one module, sources you wrote yourself | [`resident-evil/`](resident-evil/) | yes | grounding |
| A table addressed by cell, a cached page, and a claim going stale | [`steam-completion-rates/`](steam-completion-rates/) | yes | grounding, readability |
| Code quoted at a pinned commit, with permalinks, and the full SEO gate | [`plimit-concurrency/`](plimit-concurrency/) | after one resolve | all three |

```bash
npx groundtruth check examples/resident-evil
npx groundtruth check examples/steam-completion-rates
npx groundtruth check examples/plimit-concurrency
```

Each directory has a `README.md` explaining what it demonstrates and a
`WALKTHROUGH.md` that clears its findings one at a time.

## What each one is about

**resident-evil** — *The Spencer Mansion Runs on Keys.* The 1996 original as a
warehouse management problem. Grounded against 28 fact sheets the author wrote by
hand during a playthrough, which is how most real grounding folders get built.

**steam-completion-rates** — *Nobody Finishes These.* Twelve titles where length
barely predicts completion and the second achievement does. Grounded against a CSV
addressed cell by cell and a captured page, with two sources that disagree with each
other.

**plimit-concurrency** — *How p-limit works, one counter and one queue.* One file
that sits in almost every Node dependency tree, read at one commit. Every code claim
links to a line on GitHub at that SHA.

## Why they fail

Because the failures are the product. A report that is all green tells you the tool
ran. A report with two red claims tells you which two sentences you cannot stand
behind.

Each example ships a specific, chosen set of failures:

- **resident-evil**: a claim contradicted by the author's own notes, and a number
  with nothing behind it.
- **steam-completion-rates**: two source records that disagree with each other, a
  missing image, lazy alt text, and a claim that went stale when the table changed.
- **plimit-concurrency**: a claim the quoted code disproves, folk wisdom with no
  citation, and four mechanical SEO failures.

Between them they cover all four `fix.kind` values, which is the whole vocabulary an
agent needs: `edit` (a patch is attached), `rewrite` (write prose), `source` (go
find a record), `decision` (a person must choose).

## Which verdict lives where

| Verdict | Best demonstrated in |
|---|---|
| VERIFIED | all three |
| INFERRED | resident-evil, with a `derivation` naming the records and the arithmetic |
| EXTERNAL | resident-evil, a link with nothing local to check |
| FIGURE | steam-completion-rates, a number read off a chart |
| CONTRADICTED | plimit-concurrency, where the quoted code disproves the sentence |
| UNSOURCED | all three |
| STALE | steam-completion-rates, derived offline, two mechanisms |

STALE is the one people do not believe exists until they see it, and it is the only
verdict an author cannot write. The tool derives it, because a claim cannot know it
has gone stale.

## How the sources stay legitimate

Three rules, applied to all three examples.

**No third-party prose ships here.** Every source record is written by the example
author or generated by a committed script. Titles, names and dates are facts and are
not copyrightable expression.

**No third-party images ship here.** Every picture is an author-drawn SVG or a chart
generated from that example's own CSV by a committed script.

**Nothing fabricated is attached to a real thing.** The completion-rate example
invents its game titles rather than putting an invented statistic next to a real
product, and its cached page lives on `example.com`, the IANA-reserved documentation
domain. Every fabricated record carries a `synthetic` flag and a `PROVENANCE.md`
that says which numbers are invented and why.

The p-limit example vendors nothing at all. It fetches one file over HTTPS at a
pinned SHA and commits the content-addressed cache, which is both the legal answer
and the reason it runs offline.

## Reading the output without installing anything

Every example commits `expected/report.html`, `expected/index.html` and
`expected/result.json`. Open the HTML in a browser straight from the clone.

`expected/result.json` is also the regression fixture. A change to the tool that
alters what any example reports shows up as a diff there.
